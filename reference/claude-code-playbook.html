Dùng Claude Code từ ý tưởng đến release một web app

Một quy trình làm theo từng bước, đi qua Product, BA, UX/UI, Frontend + Backend, QC/QA và DevOps. Ở mỗi giai đoạn đều có: lệnh cần gõ, file cấu hình, tính năng nên dùng, và thứ bàn giao (deliverable) để chuyển sang giai đoạn sau.

Bức tranh tổng thể

Đừng coi Claude Code là một chatbot viết code. Hãy coi nó là một team ảo: bạn là tech lead, còn Claude là các vai trò khác nhau. Mỗi vai được đóng gói thành subagent hoặc skill, có hook giữ kỷ luật và CI chạy khi bạn không ngồi máy.

01ProductPlan mode, deep-research, brainstorming → PRD
02BASubagent BA, AskUserQuestion → user stories, AC, API contract
03UX/UIfrontend-design, Artifacts, Chrome → wireframe, design tokens
04Kiến trúcopusplan, Plan agent → ADR, task breakdown
05BuildWorktree song song, subagent, hooks, TDD

07DevOpsGitHub Actions, claude -p, /ship, /steward
08Vận hành/schedule, /loop, Monitor, triage log
Nguyên tắc vàngMỗi giai đoạn kết thúc bằng một file nằm trong repo (docs/prd.md, docs/stories.md, docs/adr/*.md…). Giai đoạn sau đọc file đó bằng @docs/prd.md chứ không dựa vào trí nhớ của cuộc hội thoại. Context thì có hạn, còn file thì không mất.

0.3 CLAUDE.md: bộ nhớ dự án

Chạy /init để Claude quét repo và viết bản nháp, sau đó tự sửa lại. Nếu đặt CLAUDE_CODE_NEW_INIT=1, /init sẽ hỏi thêm để set up luôn skills và hooks.

CLAUDE.md
# My App

## Stack
- FE: Next.js 16 App Router, Tailwind, shadcn/ui — apps/web
- BE: NestJS + Prisma + Postgres — apps/api
- Monorepo: pnpm + turbo

## Lệnh
- `pnpm dev` | `pnpm test` | `pnpm lint` | `pnpm typecheck`
- Test 1 file: `pnpm --filter api test -- path/to/file.spec.ts`

## Quy ước
- Nguồn sự thật cho yêu cầu: @docs/prd.md, @docs/stories.md
- API contract: @docs/api-contract.yaml — đổi API thì sửa file này trước
- Conventional commits. Không commit trực tiếp lên main.
- Mỗi story xong phải có test + cập nhật checklist trong docs/stories.md

## Không được
- Không đọc/sửa .env*. Không chạy migration trên DB production.

Thứ tự nạp: CLAUDE.md của tổ chức (managed) → ~/.claude/CLAUDE.md (cá nhân, mọi project) → ./CLAUDE.md (project, commit) → CLAUDE.local.md (cá nhân trong project, gitignore). Claude cũng đọc AGENTS.md nếu repo đã có. Có thể import file khác bằng @docs/xxx.md.

Rules theo path: đặt trong .claude/rules/. Rule chỉ được nạp khi Claude chạm vào file khớp glob, nhờ vậy CLAUDE.md gọn hơn.

.claude/rules/api.md
---
paths: ["apps/api/**"]
---
- Mọi endpoint phải validate DTO bằng class-validator
- Lỗi trả về theo RFC 7807 (problem+json)
- Query nặng phải có index; kiểm tra bằng EXPLAIN trước khi merge
Auto memoryClaude tự ghi chú những điều học được (MEMORY.md), ví dụ “user thích dùng pnpm” hay “DB prod ở Neon”. Bật hoặc tắt bằng /memory. CLAUDE.md chỉ là context, Claude có thể không làm theo. Những gì bắt buộc thì phải dùng hook hoặc permissions.deny.

0.4 Permissions: an toàn mà không bị hỏi liên tục

.claude/settings.json
{
  "permissions": {
    "allow": [

0.5 Hooks: kỷ luật tự động

Hook là script chạy ở các sự kiện như PreToolUse, PostToolUse, Stop, SessionStart, UserPromptSubmit… Khác với CLAUDE.md, hook luôn chạy. Exit code 2 sẽ chặn hành động và gửi stderr cho Claude tự sửa.

.claude/settings.json (thêm vào)
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{ "type": "command",
        "command": "f=$(jq -r '.tool_input.file_path'); npx prettier --write \"$f\" >/dev/null 2>&1; npx eslint --fix \"$f\" || exit 2" }]
    }],
    "PreToolUse": [{
      "matcher": "Edit|Write|Read",
      "hooks": [{ "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/block-env.sh" }]
    }],
    "Stop": [{
      "hooks": [{ "type": "command",
        "command": "[ \"$(jq -r .stop_hook_active)\" = true ] && exit 0; pnpm typecheck 1>&2 || exit 2" }]
    }],
    "SessionStart": [{
      "hooks": [{ "type": "command",
        "command": "echo \"Branch: $(git branch --show-current)\"; git status --short | head -20; grep -m5 '\\[ \\]' docs/stories.md" }]
    }],
    "Notification": [{
      "matcher": "permission_prompt|idle_prompt",
      "hooks": [{ "type": "command", "command": "osascript -e 'display notification \"Claude đang chờ bạn\" with title \"Claude Code\"'" }]
    }]
  }
}
  • Stop: kiểm tra stop_hook_active để tránh vòng lặp vô hạn khi typecheck không thể pass.
  • SessionStart: stdout được đưa vào context, nên mỗi session mới Claude đã biết branch, file đang sửa và story chưa xong.
  • Notification: báo trên desktop khi Claude cần bạn duyệt hoặc đang chờ, nên bạn có thể làm việc khác trong lúc chờ.
.claude/hooks/block-env.sh
#!/usr/bin/env bash
f=$(jq -r '.tool_input.file_path // empty')
case "$(basename "$f")" in .env*) echo "Không được chạm vào $f" >&2; exit 2;; esac
MẹoHook Stop chạy typecheck. Nếu typecheck fail, Claude không được kết thúc lượt mà phải tự sửa cho đến khi pass. Đây là cách rẻ nhất để có code “xanh” sau mỗi lượt. Ngoài command, hook còn có các loại http, prompt, agent, mcp_tool. Xem cấu hình đang chạy bằng /hooks.

0.6 MCP: nối Claude với công cụ bên ngoài

# Browser test tự động
claude mcp add --scope project --transport stdio playwright -- npx -y @playwright/mcp@latest
# Database (role read-only!)
claude mcp add --scope project --transport stdio db -- npx -y @bytebase/dbhub --dsn "${DATABASE_URL_RO}"
# Server HTTP có auth
claude mcp add --transport http github https://api.githubcopilot.com/mcp/ --header "Authorization: Bearer $GH_PAT"

claude mcp list         # kiểm tra
/mcp                    # trong session: xem trạng thái, đăng nhập OAuth

--scope project ghi vào .mcp.json (commit cho cả team), --scope user dùng cho mọi project của bạn. .mcp.json hỗ trợ biến dạng ${VAR}, nên không cần hardcode secret.

1Product: từ ý tưởng thành PRD

Mục tiêu: biến một ý tưởng mơ hồ thành tài liệu yêu cầu đủ rõ để bắt đầu thiết kế.

📄 docs/prd.md📄 docs/research.md📊 Scope MVP / non-goals
  1. Vào plan mode để Claude chỉ đọc, hỏi và suy nghĩ, chưa đụng tới code. 
    claude --permission-mode plan
# hoặc trong session: Shift+Tab đến "plan", hoặc
/plan Ý tưởng: app đặt lịch cắt tóc cho tiệm nhỏ ở VN...
  2. Brainstorm có cấu trúc. Skill brainstorming buộc Claude hỏi ngược lại trước khi đề xuất. Claude sẽ dùng AskUserQuestion để đưa ra các lựa chọn có sẵn (đối tượng người dùng, mô hình kiếm tiền, nền tảng…), bạn chỉ cần chọn. 
    Dùng skill brainstorming. Hỏi tôi tối đa 8 câu để làm rõ: user persona,
pain point, đối thủ, mô hình doanh thu, ràng buộc (ngân sách, thời gian, team).
  3. Nghiên cứu thị trường. Skill deep-research chia nhỏ việc cho nhiều subagent search web song song rồi tổng hợp lại thành báo cáo có nguồn. 
    /deep-research So sánh 5 app đặt lịch salon tại VN & ĐNA: tính năng,
giá, review người dùng, khoảng trống thị trường. Lưu vào docs/research.md
  4. Viết PRD. Yêu cầu một format cố định để các giai đoạn sau đọc được. 
    Dựa trên @docs/research.md và câu trả lời của tôi, viết docs/prd.md gồm:
Problem, Goals/Non-goals, Personas, Core flows, MVP scope (MoSCoW),
Success metrics (có số), Risks, Open questions,
Non-functional requirements (hiệu năng, bảo mật, a11y, i18n, SEO, uptime),
Analytics events cần đo (để kiểm chứng metrics), Compliance
(dữ liệu cá nhân theo Nghị định 13/2023, điều khoản, cookie).
  5. Ước lượng chi phí vận hành: hosting, DB, email/SMS, lượng gọi LLM nếu có, cùng các giới hạn của gói free. Ghi vào phần Risks để giai đoạn kiến trúc không chọn sai.
  6. Chia sẻ cho stakeholder. Nhờ Claude publish PRD thành Artifact hoặc Doc (trang web riêng tư, có link để share và cho người khác comment). Comment của stakeholder có thể đọc lại bằng tool, rồi Claude sửa PRD theo đó.

2BA: user stories, acceptance criteria, contract

Mục tiêu: PRD → backlog có thể làm và kiểm chứng được.

📄 docs/stories.md📄 docs/api-contract.yaml📄 docs/data-model.md📄 docs/brd.md
  1. Sinh user stories + AC dạng Gherkin. Nhờ có AC, QA sau này viết test tự động được ngay. 
    Đọc @docs/prd.md. Viết docs/stories.md: epic → story (As a/I want/So that),
mỗi story có AC dạng Given/When/Then, estimate S/M/L, dependency.
Đánh ID: AUTH-01, BOOK-03... Thêm checklist [ ] để theo dõi tiến độ.
  2. BRD chính thức nếu cần (khách hàng hoặc doanh nghiệp): dùng skill doc-brd.
  3. Data model & API contract trước khi code. Đây là “hợp đồng” giữa FE và BE, cho phép hai bên làm song song. 
    Từ stories, thiết kế data model (ERD dạng mermaid) vào docs/data-model.md
và OpenAPI 3.1 vào docs/api-contract.yaml. Liệt kê edge case cho từng endpoint.
  4. Review chéo bằng subagent để tìm lỗ hổng. 
    Dùng subagent product-manager review @docs/stories.md đối chiếu @docs/prd.md:
story nào thiếu, AC nào không test được, mâu thuẫn nào?
  5. Những thứ BA hay quên: ma trận phân quyền (role × hành động), state machine của entity chính (ví dụ booking: pending → confirmed → done/cancelled), quy tắc nghiệp vụ (múi giờ, tiền tệ, làm tròn), và các trạng thái lỗi, rỗng, đang tải, offline cho từng màn hình. 
    Liệt kê mọi edge case & business rule còn thiếu trong @docs/stories.md:
timezone, đồng thời (2 người đặt cùng slot), hủy/hoàn tiền, xóa tài khoản,
phân quyền. Hỏi tôi những điểm cần quyết định bằng AskUserQuestion.
  6. Đẩy lên tracker (nếu có MCP Linear/Jira/GitHub): “Tạo GitHub issue cho mỗi story, label theo epic”.

3UX/UI: wireframe → prototype → design system

Mục tiêu: thấy được sản phẩm trước khi viết dòng code thật đầu tiên.

🧭 User flow (mermaid)🖼 Prototype HTML🎨 Design tokens📄 docs/design/
  1. User flow cho các core flow trong PRD, viết bằng mermaid, đặt trong docs/design/flows.md.
  2. Chọn hướng thẩm mỹ. Skill frontend-design và ui-ux-pro-max có sẵn thư viện style, bảng màu, font pairing và guideline UX. Yêu cầu Claude đưa ra 2–3 hướng khác nhau. Claude có thể dùng AskUserQuestion kèm preview ASCII mockup để bạn so sánh cạnh nhau.
  3. Prototype clickable bằng Artifact. Claude dựng trang HTML tương tác rồi publish thành link riêng tư, để bạn và khách hàng bấm thử và comment trực tiếp. 
    Làm prototype clickable cho flow đặt lịch (5 màn hình), mobile-first,
publish thành artifact để tôi gửi khách hàng góp ý.
  4. Kiểm tra bằng mắt thật. Với claude --chrome (hoặc /chrome), Claude mở prototype trong Chrome, chụp screenshot, resize về cỡ mobile và tự chỉnh layout.
  5. Chốt design system thành code: tokens (màu, spacing, radius, typography) đưa vào tailwind và theme của shadcn/ui. Thêm .claude/rules/frontend.md để mọi component sau này tuân theo.

4Kiến trúc & Plan triển khai

Mục tiêu: quyết định kỹ thuật có lý do, và chia task đủ nhỏ để làm song song.

📄 docs/adr/0001-*.md📄 docs/plan.md🗂 Skeleton monorepo
  1. Dùng /model opusplan và plan mode. Built-in Plan agent (chỉ đọc) sẽ khảo sát repo và tài liệu rồi đề xuất phương án.
  2. Mỗi quyết định lớn là một ADR: chọn DB, auth, kiểu hosting, queue hay cron… Yêu cầu Claude đưa ra 2–3 phương án, trade-off và kết luận.
  3. Task breakdown theo dependency. 
    Từ @docs/stories.md và @docs/api-contract.yaml, lập docs/plan.md:
- Phase 0: scaffold (monorepo, CI, DB, auth)
- Các track song song: FE / BE / infra — đánh dấu task nào độc lập được
- Mỗi task: story ID, file dự kiến, test cần có, Definition of Done
  4. Duyệt plan. Nhấn Ctrl+G để mở plan trong editor và sửa trực tiếp, sau đó approve để thoát plan mode và bắt đầu làm.
  5. Các quyết định nền móng hay bị bỏ sót, cũng nên ghi thành ADR:
    • Môi trường dev local: docker compose cho DB, Redis, mail catcher, cộng với script seed data, để pnpm dev chạy được ngay sau khi clone.
    • Cấu hình & secrets: env schema được validate khi khởi động (zod), .env.example, secrets nằm ở đâu cho từng môi trường.
    • Observability: structured log, error tracking (Sentry), healthcheck, request ID.
    • Bảo mật: threat model ngắn (STRIDE) cho auth, upload, payment; rate limit; CORS; CSP.
    • Chiến lược migration DB: mở rộng trước, thu hẹp sau (expand → contract), backup trước khi migrate.
  6. Scaffold bằng một lượt duy nhất, ví dụ “Phase 0”. Các skill như vercel:bootstrap, vercel:nextjs, vercel:create-a-backend giúp chọn đúng pattern mới nhất.

5Frontend + Backend: build song song

Đây là giai đoạn tận dụng “sức mạnh” của Claude Code nhiều nhất: song song hóa, subagent và vòng lặp tự kiểm.

5.1 Git worktree: nhiều Claude chạy cùng lúc, không giẫm chân nhau

# Mỗi terminal một worktree + branch riêng
claude -w api-booking      # → .claude/worktrees/api-booking, branch worktree-api-booking
claude -w web-booking
claude -w infra-ci

Tạo file .worktreeinclude (cú pháp giống gitignore) để copy .env vào worktree mới. Subagent cũng có thể tự chạy trong worktree riêng nhờ isolation: worktree trong frontmatter.

5.2 Vòng lặp chuẩn cho một story (TDD)

  1. /plan BOOK-03: đặt lịch, kiểm tra trùng slot: Claude đọc AC và đề xuất các file sẽ sửa.
  2. “Viết test từ AC trước, chạy cho fail, commit test.” Commit test trước để Claude không thể sửa test cho khớp với code.

7.1 Claude trong GitHub Actions

Trong Claude Code, chạy /install-github-app: lệnh này cài GitHub App và tạo secret cùng workflow. Sau đó, chỉ cần comment @claude trong issue hoặc PR là Claude làm việc.

.github/workflows/claude.yml
name: Claude
on:
  issue_comment: { types: [created] }
  pull_request_review_comment: { types: [created] }
  pull_request: { types: [opened, synchronize] }
jobs:
  claude:
    runs-on: ubuntu-latest
    permissions: { contents: write, pull-requests: write, issues: write, id-token: write }
    steps:
      - uses: actions/checkout@v4
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          claude_args: "--max-turns 10"
          # Tự review mọi PR:
          plugins: "code-review@claude-plugins-official"
          prompt: ${{ github.event_name == 'pull_request' && '/code-review:code-review --comment' || '' }}
Dùng gói Pro/Max thay vì API keyChạy claude setup-token trên máy, lưu token vào secret CLAUDE_CODE_OAUTH_TOKEN, rồi trong workflow thay anthropic_api_key bằng claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}. Token gắn với tài khoản của người tạo, nên không phù hợp làm secret chung cho cả tổ chức.
Không muốn tự viết workflow?Code Review được quản lý: Owner của tổ chức bật trong claude.ai, mục Organization settings → Claude Ship → Review. Sau đó cài GitHub App và chọn repo. Code Review tự review mọi PR (sau khi tạo, sau mỗi push, hoặc khi comment @claude review), có các mức Quick, Standard, Deep. Tùy biến bằng file REVIEW.md trong repo. Có tính phí, nên đặt spend limit.

Sự cố production & hotfix

  1. Rollback trước, điều tra sau nếu ảnh hưởng nhiều người dùng.
  2. Dán log hoặc Sentry trace: “Tái hiện bằng test trên branch hotfix/* tạo từ tag đang chạy trên prod”.
  3. Sửa tối thiểu, /code-review high, deploy, rồi merge ngược lại vào main.
  4. Postmortem: nhờ Claude viết timeline và nguyên nhân gốc vào docs/postmortems/, rồi thêm rule, hook hoặc test để lỗi đó không lặp lại.

Bảo trì định kỳ

  • Nâng dependency hằng tuần: một routine /schedule mở PR nâng version và chạy test.
  • Triage feedback và issue mới: phân loại, gắn label, tìm issue trùng.
  • Retro với chính Claude: mỗi khi Claude làm sai cùng một kiểu lần thứ hai, thêm vào CLAUDE.md, rule hoặc hook. Bộ cấu hình .claude/ tốt dần theo thời gian.

Vòng lặp tiếp theo: feedback từ user → cập nhật docs/prd.md → story mới → quay lại giai đoạn 2. Nhờ mọi thứ nằm trong file, vòng lặp sau nhanh hơn vòng đầu rất nhiều.

Bẫy thường gặp

❌ Một session khổng lồ làm mọi thứ

Context bị loãng thì chất lượng giảm. ✅ Mỗi story một session (/clear), và state nằm trong file docs/.

❌ Để Claude viết cả test lẫn code cùng lúc

Claude dễ sửa test cho khớp với bug. ✅ Commit test trước, ghi rõ “không sửa test”, và thêm hook chặn sửa *.spec.ts ở bước implement nếu cần.

❌ Nhét mọi quy tắc vào CLAUDE.md

File dài thì Claude bỏ sót. ✅ CLAUDE.md dưới 200 dòng, chi tiết đưa vào .claude/rules/ theo path, quy tắc bắt buộc thì dùng hook hoặc deny.

❌ Bỏ qua plan mode cho task lớn

Sai hướng từ đầu thì tốn gấp mười lần để sửa. ✅ Task nào trên 3 file thì /plan trước, đọc plan rồi mới cho chạy.

❌ Cho quyền rộng ở môi trường thật
